# sml-codes

SML 错误码常量与带码错误类型（唯一事实来源：`errors/codes.sml`）。

**English below** ｜ 中文在上方，English 在下方

# 中文

`sml-codes` 是**语言层错误码**的落点：`sml-lex` / `sml-parse` / `sml-contract` /
`sml-include` 都从这里取码，从而保证「同一触发条件五端同码」。

它**零依赖** —— 码是契约，不该反过来依赖任何实现。

## 安装

```toml
[dependencies]
sml-codes = "0.1.0-alpha.1"
```

## 用法

```rust
use sml_codes::{SmlError, E_PARSE_008};

let e = SmlError::new(E_PARSE_008, "顶层须为容器（键值块、对象块或数组）");
assert_eq!(e.code(), "E-PARSE-008");
assert_eq!(e.to_string(), "顶层须为容器（键值块、对象块或数组） [E-PARSE-008]");
```

## 两条约定

- **码是稳定契约，文案不是**。码来自 `errors/codes.sml`（生成，勿手改），
  文案随便改；用户脚本应当判断码而不是文案。
- `Display` 把码缀在文案之后，而 `From<SmlError> for String` **只取文案** ——
  后者是给本仓库既有的 `Result<_, String>` 接口留的兼容通道。

## 生成物

`src/codes.rs` 由 `errors/gen_codes.py` 生成（同一份码表还生成
`js/sml-codes.mjs` 与 `c/sml_codes.h`）。改码表后重跑：

```bash
python errors/gen_codes.py          # 重新生成
python errors/gen_codes.py --check  # 只校验（CI 用）
```

# English

`sml-codes` holds the **language-layer error codes**: `sml-lex` / `sml-parse` /
`sml-contract` / `sml-include` all take their codes from here, which is what makes
"same cause, same code" checkable across implementations.

It is **dependency-free** — a code is a contract and must not depend on any implementation.

## Install

```toml
[dependencies]
sml-codes = "0.1.0-alpha.1"
```

## Usage

```rust
use sml_codes::{SmlError, E_PARSE_008};

let e = SmlError::new(E_PARSE_008, "top level must be a container");
assert_eq!(e.code(), "E-PARSE-008");
```

## Two rules

- **The code is the stable contract, the wording is not.** Codes come from
  `errors/codes.sml` (generated, do not edit by hand); wording may change freely.
- `Display` appends the code to the message, while `From<SmlError> for String`
  yields the **message only** — a compatibility channel for the many existing
  `Result<_, String>` APIs in this repository.

## Generated files

`src/codes.rs` is generated by `errors/gen_codes.py` (the same table also produces
`js/sml-codes.mjs` and `c/sml_codes.h`).

```bash
python errors/gen_codes.py          # regenerate
python errors/gen_codes.py --check  # verify only (CI)
```
