## 0. 「算不算 v5」的判定规则

用户 2026-11-03 定：**crates.io 上最后一个 stable 之后引入的语法，全部算 v5。**
⇒ 不逐条判别「是不是破坏性」，只问「它是否已在 stable 里」，不在就是 v5。

**尚未定稿的两点**：

- v5 一旦随下一个 stable 发布，之后的新语法是继续进 v5 还是转 v6（**未定**）；
- 本文表 A 全部为**草案**，未实现（`Version::CURRENT` 仍是 `V4`）。
- ⚠️ **版本表示本身也要改**（用户 2026-11-04：版本号 = 功能集；稳定前只有开发代号）⇒
  见 `docs/version-naming.md`。**「加一个 `Version::V5` 枚举项」这条已作废。**

## 表 A · 语言层（用户要改的是 `.sml` 文档）

| # | 改动 | v4 现状 | v5 行为 | 状态 |
|---|---|---|---|---|
| A1 | **featag 声明**（契约体内 `!name` / `!name: 类型` / `!name: 类型 -> 落点`） | 不存在 | 新增 | 🟡 草案 v1.0 |
| A2 | **featag 使用**（块头 `wea !critical obey[1,2], name { }`） | `!x` 是普通裸词 | 新增 | 🟡 草案 v1.0 |
| A3 | **`__featags`** 元数据键（保序数组） | 无此键 | 新增 | 🟡 草案 |
| A4 | **`from-featag`** 字段修饰符（该键只能由 featag 写） | 无 | 新增 | 🟡 草案 |
| A5 | **`!any`** 契约级开关（允许 `any`） | — | 新增 | 🟡 草案 |
| A6 | **`!strict-paths`** 契约级开关（关掉「落点父对象自动创建」） | — | 新增 | 🟡 草案 |
| A7 | **`any` 默认禁用** | `any` 合法 | 需 `!any` | 🟡 草案 |
| A8 | **正文手写 `__*` 报错** | 原样保留（**实测可伪造 `__type`**） | 报错 | 🟡 草案 |
| A9 | **`!` 歧义一律报错**（值位置 `a: !b` / 块名以 `!` 开头 / 空 featag 区 / 声明重复名） | 无此规则 | 报错；`"!b"` 加引号才行 | 🟡 草案 |
| A10 | **`auto` 占位值**（`obey[auto]` = 取声明默认值） | 普通裸词 | featag 参数槽内有特殊含义 | 🟡 草案 |
| A11 | **`@feature enable <域>.<名>`**（如 `type.featag`） | 不认带点名 | 认，且只在第一个点切一次 | 🟡 草案 |

> 一句话概括 A1–A10 的一句：**`!` 只在「块头契约名之后」被当记号，其它位置出现即歧义即报错。**

   否则用户分不清「我的 `.sml` 要不要改」和「我的 Rust 代码要不要改」；

   必须逐端写清（`E-FEATURE-004` 的 note 已有此结构，跟着改）。
