# null / none 语义清点（v0.1 · 2026-11-04 用户已定五条）

> 来源：`docs/feature-namespace-plan.md` §4.55「v5 尽可能减少 null / none 思维」，
> 用户 2026-11-04 逐条点头。**本文件只做设计 + 现状实测，零代码改动**；
> `IDEAS.md` / `TODO.md` 未动。

---

## 1. 五条规则（已定）

| # | 规则 | 备注 |
|---|---|---|
| **N1** | `Value::Null` **保留**（接外来 JSON 必须有），但契约里**不鼓励**用它表达「没有」 | 「减少 null 思维」是**写法引导**，不是删类型 |
| **N2** | `optional` = 键**缺失**；写 `null` 是**值**，按类型校验 ⇒ 与 `int` 不符就报错 | **现状已经如此，只需明文化**（零实现成本） |
| **N3** | `default null` **v5 起禁用**（v4 保持合法） | 「默认值给 null」= 主动塞一个「有的空」；要「可能没有」请写 `optional` |
| **N4** | 开了 `!any` 之后，`any` 里**允许** null | `any` 的定义就是放弃校验；禁 null 会造出「any 但不能是 null」的特例 |
| **N5** | 输出侧 null **不产出**（跳过），并补跨端用例 | 现状三处三样，见 §2，属**真实漂移** |

## 2. 现状实测（2026-11-04）

探针文档：

```sml
a: null
b: [ null 1 ]
c { d: null }
```

| 端 | 通路 | 实测结果 |
|---|---|---|
| **Rust** `--to json` | 值模型 | `{"a":null,"b":[null,1],"c":{"d":null}}` —— 原样保留 ✅ |
| **Rust** `--to md` | `emit/markdown` | **顶层 `a` 被丢掉**；数组只出 `1`（null 元素丢失）；对象字段出 `- **d**: (空)` |
| **Rust** `--to html` | `emit/html` | `a` 与 `d` 都渲染成 `<strong>a</strong>: (空)` —— **与 markdown 不一致** |
| **JS** `parse` + `dump` | 无 emit 后端 | parse 保留 null；dump 写回 `null` ✅ |
| **C / C++ / Lua** | **只有 dump（无 emit 后端）** | ⬜ **未跑**（本轮未做运行时探针；需各补一条 null 往返用例） |
| **Rust** `latex` / `svg` / `slint` / `xml` / `custom` | 各 emit 后端 | ⬜ **未测** |

**由此得出一个重要事实**：全仓**只有 Rust 有 emit 后端**；C / C++ / JS / Lua 只有
「解析 + 序列化回 SML」（dump）。所以 N5 必须拆成两件事，否则范围会估错：

| 子项 | 范围 | 现状 |
|---|---|---|
| **N5-a** | **dump 五端一致**：`null` 必须原样往返成 `null` | Rust/JS 已知 ✅；C/C++/Lua 待补用例 |
| **N5-b** | **Rust emit 各后端一致**：null 一律**不产出** | ❌ 现在 md 丢弃、html 写 `(空)`，**同一份文档两种结果** |

## 3. 需要定的一处细节（N5-b 的边界）

「不产出」有三种可能，行为差别很大：

| 方案 | 顶层 `a: null` | 对象字段 `d: null` | 数组 `[null 1]` |
|---|---|---|---|
| **① 整条跳过**（建议） | 整行不出现 | 该字段不出现 | 只出 `1` |
| ② 写占位文本 | `(空)` | `(空)` | `(空), 1` |
| ③ 报错 | 报错 | 报错 | 报错 |

**建议 ①**：输出是给人/文档看的，「没有内容」就不该占位；② 会让生成长文时到处是 `(空)`；
③ 太激进（null 是合法数据，只是没有输出物）。

⚠️ 但注意：**①会让「数据里有 null」与「键不存在」在输出里不可区分**。这是可接受的 ——
输出层本来就不承诺可逆；要可逆请用 `--to json` / `--to sml`。

## 4. v5 门槛

| 规则 | 对 v4 的影响 |
|---|---|
| N2（明文化） | 无（现状即如此） |
| N3（`default null` 禁用） | **breaking** ⇒ 只在 v5；v1–v4 保持合法 |
| N5-a / N5-b | 输出行为变更 ⇒ 挂 v5（但可先按「修 bug」在 Rust 内部对齐，登记其余端差异） |
