## 1. 主线（按轮次推进，不合并成结论）

### 1.1 纠偏：这是创新讨论
背景文档被当成「接下来的背景」引入；助手上一轮把它复述成了一组待守的规矩，用户当场纠正：目的是创新，文档内不是系统提示词。此后按抽象探讨走：逻辑模型、可能性、边界、反例，不推开发、不落文档、不裁决。

### 1.2 随时中断 × 锁 × sml × 多写者
切入是四问合一：程序随时可能中断时，锁的粒度、为什么要和 sml 结合、什么样的数据可以多写者、强行多写者如何让逻辑简单可预测。

讨论里浮现的判断：随时中断把「锁保护一小段时间」打穿，断电不挑临界区，锁自己也会没，地上只剩半截字节；可判之物只剩「一块自带完整性自证的状态」。锁切细只提高并行度，不提高中断安全；等待几乎全来自落盘而非锁的粗细。「提交成功」可改写成「写出一条能被独立判完整的记录」，中断从「状态坏掉」降级成「少一条观察」。

结合点：存储层只看见字节，判不了「哪几个属性必须一起变」「这块归谁」；语言层声明写单元边界和所有权，持久化层只保证「在字节里、可寻址、可验证」。边界进不了类型就只能靠约定，而约定可以撒谎。

多写者的分界不按冷热、大小，按**合并是否与顺序无关**。a、b 都看到 sa 而 sa 变了，坏的不是并发，是「写同一对象的同一属性却没定义合并」。反直觉的一招是不协商、直接取消共享：各写各的槽，只追加自己的观察，读端纯函数折叠；于是无锁、中断安全、物理序不进结果、因果可判。代价：结果不再是「一个当前值」而是「一组观察」，跨属性强约束可能在折叠时被打破，元数据可能比数据大；要单一当前值，唯一取号点（锁与单点）一起回来。

### 1.3 路径机制、锁过度与「现实里人会怎么操作」
用户给出 apt 类比：装 a、装 b，并不操作同一部分，锁整个文件是过度。讨论里把过度的根源指为**边界由容器画**：整份文件、整个状态库，跟实际碰到的那几块对不上。路径机制让「这一块」能被单独谈，判据从「锁多细」换成「两个写者声明要碰的路径集合相不相交」——这一步只有语言层给得了。

现实类比：人不锁整间屋子，各占一个本子一张柜台；留条子写名字、写「接着上一张」，人中途走了条子还在，不需要锁还在；两个人各记一笔，没人当场合成「现在的值」，事后对账；活事先分好，不临场抢。最要紧的是人从不假设一件事会连续做完，所以**每一步都做成能独立留在那儿的东西**。

「另辟蹊径」落在：编译期那套靠「这次运行是连续的」把顺序钉死；一旦随时中断、存完再散着慢慢聚合，编译期看不见运行之后那段。确定性来源换掉——不预先排好序，而让两条记录根本不争同一个位置；可预测不来自「有序」，来自「不相交」。边界：真跨块的约束或运行时才分得清碰哪块，得添公共账本、一个人管账，唯一取号点就回来了；条子攒多对账变贵，那正是「后面慢慢聚合」该待的地方。消掉的是无谓等待，不是所有协商。

### 1.4 软落盘、智能整理与「分支记状态」
用户提出：写过程（特殊模式下）先落下自己的改动，用软方式实现效果一样；之后按系统负载、程序任务，让库用户智能地碎片整理。新思绪是 amberice 的名字——程序员在写程序时就能在各分支记下程序状态，不可预测中断、bug 处理会更优雅，也为形式化证明铺路。

讨论里把两段合为一件：**把「发生」和「算数」拆开**。改动先在程序里发生，落盘交给负载挑时机；「软方式效果一样」靠的不是模拟写盘，而是软记录自己完整、可重放、可丢弃。中断不再打断一个动作，只是某次落定没赶上，观察还在。调度越自由，越不能靠「字节在盘上」回答「什么时候算数了」；可整理的也就不只是文件，还有那些还没算数的观察。

分支记状态是同一招搬到控制流：琥珀凝固的是那一瞬的断面，不是液体怎么流过来的。每个分支点留得下状态，程序就不再是一条必须连续走完的线，而是一串各自能站着的断面；中断和 bug 从「线断在哪找不回」变成「哪两个断面之间没走完」；形式化证明铺路，多半因为证明最怕隐式状态，断面把状态摆明后，对象从一段执行变成「断面 + 转移关系」，更像不变量归纳。

留下的张力：两处都要求「算数」不依赖时机，可一旦过程也能留、软记录也能算数，结果与过程的界不再是信封自己划得清的。

### 1.5 分层、trait 与「面不是点」
用户：库贯彻分层思维，从抽象到具体，不造成大面积重写，少影响用户的控制细粒度；记录状态用 Rust trait 等高级特性半自动做，不要人打桩，是面不是点，「自动」地细化。

讨论里：「面不是点」戳中打桩最要命处——桩是人挑的，覆盖没法证，漏一个分支就漏一个断面，证明反而得先证「桩没漏」。trait 反过来，声明落在类型/能力上，所有实现它的状态、所有走这条路径的值都自动带上，覆盖是编译器给的。半自动的分工：人在最抽象层给模式和边界，机器往具体里细化到每个分支、每个中间态；编译期铺的是规则的面，运行期落的是断面的点，点由面生成，不必预先排好序。

分层解的是「成面覆盖」与「不大改用户代码」：加的不是控制流里的桩，而是与用户控制流并排的一层观察面；声明在最上，落到字节与调度在最下，中间把属性翻成策略。属性不是标签，是编译器能据以判定的能力。张力：自动细化把断面铺得很密，哪些「算数」、哪些只是流过的痕迹仍需判据；要人逐条标就退回点了，由属性自动判则属性得先能回答「过程算不算结果」。

### 1.6 不确定、因果链与复合描述
用户：一段代码之所以值得跑，核心是有不确定的部分（用户行为、从外界读取的信息）；当这些事件、交互发生……因果链能否被追踪，程序运行状态能不能用库和人自己想要的来复合描述。

讨论里：确定的部分不值得跑，能算出来的编译期就该算完；运行不是「沿着线走」，是**把外界进来的不确定一点点消化成确定**，状态不是「停在哪」而是「还剩哪些没消化」。中断只让消化停在一个断面，恢复不必回放整条线。因果链不追「谁先谁后」，追**谁看见了谁**：外部事件自带身份注入，每个断面记下自己见过哪些事件，因果是集合的包含关系，物理序和时钟进不了结果。a、b 都看见 sa 而要判的，是两份观察声称的前驱集合是不是同一份 sa 的两个版本。

复合描述的接口：库给「这块怎么独立站住、怎么折叠、怎么验」，人给「什么算一个事件、哪几个算同一件事」，接在一次声明上由库细化成面。「哪些算数」顺带落地——由确定规则从事件推出的可重算、不必存；事件本身和人对它的切分不可重算，才算数。证明对象从执行轨迹换成「事件集 → 状态」的纯函数加偏序。硬条件：人那半也得是编译期看得见的声明；运行时能随手改「什么算一个事件」，事件就没稳定身份，因果和证明一起塌。

### 1.7 示例代码形态
用户要「一个示例代码形态」。给出形态示意（非可编译实现，全文见附录 B）：`#[event(identity = ...)]` 冻结事件身份；`#[aggregate(key, fold = join, process = evidence)]` 声明不可分写单元；用户控制流原样 `match`，每个分支出口过同一个 `IntoFrame`，由派生铺成面；`Frame` 自带 `seen: EventSet`、`pending = E \ seen`、`digest`；中断后 `disk.frames().filter(Frame::valid).fold(Quote::bottom(), Join::join)`，物理序不进结果。硬条件：`fold` 必须是半格，换成 LWW 之类要时钟的东西，因果退回物理序。

### 1.8 关键位置显式 trait；模式 / 任务
用户：关键位置的突发情况处理应该是显式的 trait；还有模式、任务这种，「我在想......」。

讨论里：显式 trait 不是把桩请回来，是把「例外」抬进类型层。自动派生铺常规分支出口，默认每个断面都能被 `join` 吞掉；突发恰是 `join` 吞不掉的——该来的事件没来、两份观察认了互斥前驱、写到一半断了；那不是「多一个 Frame」，是 `pending` 不收敛，半格走到边界给不出值。人点的仍是抽象那层（哪处算关键、断了拿什么顶），编译器从这点铺到所有实现该 trait 的状态，所以还是面。示意 `trait OnBreak: IntoFrame { type Alt; fn on_break(pending: EventSet, cause: Break) -> Frame<Self::Alt>; }`。

模式 / 任务像再往上：不改控制流，也不进字节，只改「同一批断面现在按什么解释」——存模式、聚合模式、证明模式、抢救模式；任务是模式的一次带边界的实例。「智能整理」不是库自作主张，是模式先声明了允许怎么收；库给机制、人给意图，复合描述从两方变三方。未收口：模式一多，「算数」的解释权会从属性滑到模式；换模式本身不留痕，事件身份那层冻结就被绕开。模式要不要也做成 trait、任务能不能被证明，都还没定。

### 1.9 摘掉数据：长任务、长路径
用户明确「和数据暂时无关」：如果程序可能被随时中断，操作路径又很长 / 任务很长。

讨论里：长任务的敌人不是步骤多，是**它默认自己会连续活着**。传统写法里任务的存在挂在「当前执行到哪」一个指针上，指针一没，地上剩下的东西回答不了「做到哪了」；难的不是续跑，是任务本来没有独立存在的形式。口子：把「完成」从**时刻**改成**从已留下的断面里可判出的性质**——不设最后一步那个位置，断之前断之后同构，恢复是重新判一次性质，而非回放整条线。

「长」还带一件短任务没有的事：路径长到中途，外部陆续进来、目标可能被修正，起点写死的计划和终点实际做的事不再同一个；要判的从「做到哪了」变成「这还是不是那个任务」「前半段的结论还算不算」。绝大部分步确定可重算，丢了重来，真要留的只有不可重来的点；成本不随路径长度长，只随不可重来的点数长。留一个不收口的：任务身份凭什么跨过中断还是同一个，而不是悄悄重开了一个。

### 1.10 中断和恢复的两个时刻
用户点出「中断和恢复的两个时刻」。

讨论里：常规把这两个时刻当成任务的两个状态，中间焊一段空白，靠指针或快照补上；可「没跑完」是相对那条连续线才成立的概念，线本就不存在，暂停也就不存在。中间那段时间里任务既没在跑也没在等，它不在时间轴上；所谓两个时刻只是同一个问题被问了两次：从留下的东西看，这任务成立吗。

更怪的不对称：中断并不留下标记，断面里没有「断于此」这一位，恢复却要装作有那么个位置可接——checkpoint 就是伪造的那一处。承认没有，恢复便不是「接着断口」，而是和任何一次普通观察同构的重新判一次；中断时刻也不比别的时刻特殊。真正跨过去的不是内部状态，是外部：恢复时世界已经不是那个世界，隔在中间的不是空白，是又一批没消化的不确定。于是「恢复」这个词大概本身就该消失。

### 1.11 通过层层抽象做这些？
用户问「通过层层抽象做这些？」。

讨论里：层干的不是封装，是**把一次长执行换成几层各自能独立被问一次的判断**——最底「这块能独立站住吗」，上一层「几块合起来还成立吗」，再上「这还是那个任务吗」，最上「这次按什么解释」。中断落在任意一层，那层自足，上层不必知道下层断过；每层被重新问的是同一句话。「恢复」没有位置，长路径变成 N 个短断言，断言之间不存在「接着」。层层抽象替代的正是那条连续线：不是把长度藏起来，是不再需要长度。

代价：层天然往上擦细节，可中断留下的偏偏是细节（外部又进来了、哪一步没赶上）；所以每层不能只朝上，得留向下无损穿透的口子；「算数」的解释权也不能在层间滑。层是编译期铺的面，跨过中断的却是这一次实例，身份不归层管。未收口：层与层之间那次「下推」自己算不算一次操作？算，它也能被中断——要么无限退层，要么得承认最底下有一层不可再分、且不许断。那一层是什么，还没定。

### 1.12 A-Aa-Aa1：每一步天然带标、更好缩放
用户：这样每一步动作天然会有可以追溯的标，同时会更好地缩放；我要做 A-Aa-Aa1，这样复杂程序会变清晰。

讨论里：要害不是层级，是**标不另发**——身份从前缀里推导，Aa1 自带「见过 A 与 Aa」；前驱不必另记、时钟不必取、中心不必发号。上轮悬着的「凭什么跨过中断还是同一个任务」，路径本身就是一种答法。人只给根 A，命名规则由编译器铺到每个分支出口，仍是面。缩放吃前缀共享：确定步丢了重来，只留不可重来的点；寻址按深度不按步骤总数；散着的断面凭前缀自己归位，「后面慢慢聚合」不必全局对账。复杂变清晰，是因为「这步属于哪个任务」从控制流里的隐式事实变成一次可问的判断。

洞在单父：树只有一个前驱，可 a、b 都看见 sa 那类断面的 `seen` 是集合；给 Aa1 选一个父亲，等于把另一半因果删了，或悄悄把顺序放回来。要保「谁看见了谁」，标得是路径的集合而非路径——那 Aa1 就不再叫 Aa1，可读性也跟着掉。另有一处：若 Aa 下长 1 还是 2 得等外部事件消化完才定，路径就由运行时生成，身份又依赖时机了。**树让人看清，集合不撒谎；两者要不要合成一个东西，没定。**

## 附录 B · 示例代码形态（§1.7 全文）

> 形态示意，不是可编译实现；重点看「谁声明什么」。

```rust
// 层 1｜人只声明：什么算一个事件，身份从哪来。编译期冻结，运行时改不了
#[event(identity = "order_id")]          // 身份不取时钟，也不取到达顺序
struct PriceSeen   { order_id: OrderId, v: i32 }
#[event(identity = "order_id")]
struct UserConfirm { order_id: OrderId, choice: Choice }

// 层 2｜人声明：哪几个算同一件事、哪几个属性必须一起变
#[aggregate(key = "order_id", fold = "join", process = "evidence")]
struct Quote { price: i32, choice: Choice }   // 一个不可分写单元

// 层 3｜用户控制流原样，不打桩
fn on_event(q: &Quote, e: Event) -> Frame<Quote> {
    let next = match e {
        Event::Price(p)   => q.with_price(p.v),
        Event::Confirm(c) => q.with_choice(c.choice),
        // 每个分支出口都过同一个 trait，覆盖由编译器铺成面
    };
    next.record()   // 效果先发生；落盘时机交给负载，不在这里
}

// Frame 由 IntoFrame 自动派生，人一行都不写：
//   seen: EventSet      自己见过谁 → 因果是集合包含，不是先后
//   pending = E \ seen  状态 = 还剩哪些不确定没消化
//   digest              独立站住、可验；半截的可直接丢

// 中断之后 / 散着慢慢聚合：物理序不进结果
let frames = disk.frames().filter(Frame::valid);   // 校验不过 = 没算数
let q = frames.fold(Quote::bottom(), Join::join);  // 结合 · 交换 · 幂等
```
