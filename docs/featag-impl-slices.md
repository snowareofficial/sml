## 2. 键名白名单（S1，用户 2026-11-04：白名单策略）

| 允许 | 说明 |
|---|---|
| `A-Z` `a-z` `0-9` | ASCII |
| `_` `-` | 下划线与连字符（路径分隔只用 `.` 与 `[]`，不与它们冲突） |
| **CJK 统一汉字**（U+4E00–U+9FFF） | 中文键名是既有能力（`svg`/`slint` 会被 sanitize，但数据层允许） |

| 拒绝 | 理由 |
|---|---|
| `.` `[` `]` | 路径语法保留 |
| 空白 / 控制字符（Cc） | 不可见 |
| **格式字符 / 零宽 / 双向控制（Cf）** | 不可见、可伪造显示 |
| **西里尔 / 希腊等同形字母** | 同形字攻击（`а` vs `a`）—— 白名单天然排除 |
| 全角标点、兼容区字符 | 与半角混用会造成「看起来一样、比较不等」 |

### 2.1 同形字：**只允许一种字形**（用户 2026-11-04）

> 原话：「字形相似的字母只能有一种，**声明时**」「特别是英语、西里尔那种」。

- **检查点在声明处**：契约名、字段名、featag 名 —— 不只是数据键；
- 允许的字形：**ASCII 拉丁** + **CJK 汉字**；**西里尔 / 希腊 / 亚美尼亚**等一律拒（`а`(U+0430) 与 `a` 不可共存，直接不允许前者出现）；
- ⚠️ **实现要求**：白名单是**字符范围表**，必须**生成到五端**（像码表那样），不许各端手抄范围 —— 否则「哪端放到多宽」迟早不一致。

### 2.2 NFC：**强制**（用户已定）

- 检测到非 NFC 即报错；
- 💡 **零依赖的实现路径**：当前白名单只有 ASCII + CJK 基本区，**这些字符都是 NFC 稳定的**
  ⇒ 只要再拒绝「组合标记（Mn / Mc）」，NFC 就自动成立，**不需要归一化库**；
- ⚠️ 但这条只在「不允许带变音符号的拉丁字母（`é` / `ü`）」时成立 —— 若将来允许，就必须真做 NFC
  （需要数据表或 `unicode-normalization` 依赖，破零依赖）。**这条待你定**。
