## 四、定位

- **SML**：声明式配置/数据格式。核心卖点不是语法，而是**五端逐字节一致**（向量 + 对拍 + 差异台账）。

- **swml**：门面/品牌层（原 `smlkit` 坑位），未建。

## 六、仓库拆分方案（未执行）

目标：`swml` / `amberice` 有独立 GitHub 仓；`swsml` monorepo 仍是根仓库。

### 三步

1. **`amberice` 先做只读镜像**
   ```bash
   git subtree split -P rust/amberice -b amberice-split
   git push github amberice-split:main
   ```
   独立仓接收 issue，不接收 PR（PR 回到 monorepo）。monorepo 仍是唯一代码源。

2. **`swml` 建占位仓**（只放 README），等命名定完再填。

3. **`amberice` 真正独立**（可选，暂不做）
   前提：`sml-value` 发 crates.io、`amberice` 依赖版本号而非 path。
   代价：拆 workspace、发布顺序、CI 联动。`amberice` 仍在快速演进，拆出去后每次改动要跨仓同步。

### 前置条件

`amberice` 依赖 `sml-value`（monorepo 内），`amberice-ffi` 又依赖 `swsml`（可选 feature）。
若独立仓要**接收 PR**，这两条依赖必须有 crates.io 版本，否则外部贡献者拉不下代码。

顺序：发 `sml-value` / `swsml` 正式版 → `amberice` 依赖版本号 → 再开放 PR。

## 七、amberice 的潜在用途

| 场景 | 用什么能力 |
|---|---|
| 发布产物签名 | 层链 + Ed25519，`amberice sign` / `verify` |
| 可增量更新的配置包 | 分层追加（`append`），不重写旧字节 |
| 多语言共享数据 | 五端解码器（Rust/C/C++/JS/Lua）+ 绑定 |
| 加密载荷 | `dump_encrypted`（AES-256-GCM）+ 段级压缩 |
| 嵌入式配置 | C99 解码器，无第三方依赖 |
| CI 归档 | `pack --zstd` 打包多个文件，`unpack` 取回 |
| 审计链 | 每层带作者签名，`tree` 看层链 |

注意：目前只有 CLI 与库，没有开箱即用的上层应用。
