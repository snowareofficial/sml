### 2.1 多契约（`bff4af0`）

照 Rust `apply_contracts` 的**合并视图**：字段并集、严格度取最严、同名字段冲突 ⇒ `E-CONTRACT-016`，
然后**复用各端既有的单契约入口**。三处应用点：`@is` 多契约 / 字段级 `@is` / 块头 `A B item { }`。

两处口径容易写错：`required` **不在**冲突预检内（取或）；`warn` 在四端按 `loose` 记（值树相同、
诊断不同）。

### 2.2 featag 的 `!` 与区位置（`caeab7a` → `eb9b2c4` → `f59a074`）

**中间那次是回退**：先把四端补成「带参项可省 `!`」（对齐当时的 Rust），随即撞上一条更根本的问题 ——

```sml
A B rep[3], prod { }      # rep 既是 A 的 featag 名，又有一份 @contract rep
```

Rust 报 `012`，四端却把 `rep[3]` 当 featag 收下。「连续命中契约表的词算契约词」与「`名[` 算 featag」
争用同一个裸词，只能靠先后次序猜 ⇒ **改语言而不是打补丁**：

```
契约词  [ !featag … ]  [,  块名]  { … }
```

- 每一项都带 `!`（`!critical` / `!obey[1, 2]`），`!` 是 featag 的**唯一**标记；
- 区**紧跟契约首词**，之后才是其余契约词与块名；
- 区收完不是 `{` ⇒ 兜底 `012` 且**不回退**；区外的 `!` 词 ⇒ `027`；无契约却写 featag ⇒ `021`。

`f59a074`（I-27）在其上加了一条：**首项必须 `!`（锚点），区内后续项可省**，判据是「该词命中
当前契约的 featag 声明」——

```sml
A !t u, one { }   # u 在 A 的声明里 ⇒ featag
A !t B three { }  # B 不在声明里 ⇒ 仍是契约词（多契约不受影响）
```

**为什么判据必须是「查声明」**：若用「区内裸词一律算 featag」，`A !t B` 里的契约词 `B` 会被吃掉，
多契约与 featag 就没法共存。

### 2.3 `@type` 四端（`646588c`）

`@type name: X { 模式 }`，四端各一台 **Thompson NFA**（与 Rust `sml-pattern` 同构，无回溯）：

| 端 | 位置 |
|---|---|
| C | `c/src/02b_pattern.inc`（新模块，排在契约之前） |
| C++ | `cpp/src/02b_pattern.inc`（`TypeSpec::Kind::Pattern` 持有 `shared_ptr<Pat>`） |
| Lua | `lua/lib/sml.lua` 的「模式语言」一节（模块级 `_TYPES`） |
| JS | 原有，走 **RegExp**（不是 NFA） |

三件事必须五端一致，否则「同一份文档一端过、另一端报 009」：

1. **字符类按 Unicode**（`数字` 不止 `0-9`）。四端各写各的区间必然漂移 ⇒ 由
   `tools/gen/gen_unicode_tables.py` 从 Rust 的 `char::is_numeric / is_alphabetic / is_whitespace`
   逐码位导出同一张表（`c/sml_pattern_unicode.h` 给 C / C++，`lua/sml_pattern_unicode.lua` 给 Lua）。
   生成器本体是 `rust/sml-pattern/examples/gen_unicode_tables.rs`。
2. **无回溯**：量词编译成 ε-转移、模拟时所有线程并行推进；单量词 ≤ 1000、指令总数 ≤ 100000、
   步数预算 1000 万（与 Rust 同数同义）。
3. **同因同码**：编译失败（循环引用 / 未定义规则 / 坏元素 / 量词过大）⇒ `013`；
   值不符（或非字符串）⇒ `009`。**没被引用过的坏模式不报错**（编译发生在字段类型解析处）。

`[D]` 的元素不符要带下标（`v[1]`）—— C 那边一开始报通用 002，与 Rust 的 009 有差距，已修。

### 2.4 数组位置的裸块（`be34e59`）

`xs: [ A B item { } ]` 在 Rust 里是**一个**块元素。此前 C/C++ 报 017、JS/Lua 拆成 4 个标量。
C/C++/Lua 补齐（featag 区、多契约前缀、拆雷、012、`__name` 起点、S7/S6、合并视图应用契约）。
C/C++ 的实现从 `04*` 挪到 `05_parse.inc`（S7 的 `check_from_featag`、S6 的 `write_target` 在那）。

⚠️ **深度守卫**：数组里的块是数组的**子级**，`parse_array_bare_block` 内部已经 `parse_block(depth+1)`，
外层不能再 `+1`（多算一层把「128 层放行」压成 64 层，Lua 侧实测踩到）。

### 2.5 dump 值位置（`73dfcc6`）

JS / Lua 的 `stringify` 在**值位置**也写块头（`S: S prod { … }`），而值位置的裸块头不是合法 SML ⇒
Rust 回读报 `006`。改成「块头只在**键位置**成立，值位置一律写扁平对象」。
同轮还修了 **Lua 的数组字符串绕过 `needs_quote`**（`tostring(e)` 直接写）—— 那才是整份 `grammar.sml`
读不回来的主因（`live: [ "@version …" ]` 被当指令）。

## 3. 本轮定下的语法规则（三处裁决）

1. **`@is` 多契约一律逗号分隔**（`@is A loose, B`）。逗号之后是「新的一段」，与块头三段式同习惯。
   省略逗号的连续词写法**仍按连续契约词解析**（兼容），但不作为规定写法。
2. **featag 每项带 `!`，区紧跟契约首词**（§2.2）。
3. **I-27 例外**：区内后续项可省 `!`，判据是命中当前契约的声明。

三条都已写进 `featag.md` §2.2 / 台账 §4.5b，并同步 `grammar.sml` 的活示例、`v5.md` 表 A2、
`featag-slices.md` S3。

## 4. 已知差异全景（都已登记，无未记录项）

以下全部在 `docs/swsml/ref/grammar-divergences.md`，**接手先读它们的当前值**。

### 4.1 数字身份（探针唯一不一致，`94/5` 里那 5 行同源）

`Lua` 把 float `1.0` 写成 `1`；`JS` 的 `i64` 走 `BigInt` 语义；`num-sci` 的 `1e3` 在 C/C++ 变 `1000.0`。
**值与 JSON 层都一致，差的只是「整数 / 浮点」的身份**。属值层项目（§0 R-2），不是解析差异。
本条同时是 `probe_grammar` 停在 1/20 的原因。

### 4.2 JS 的数组位置裸块（§4.5e 剩余）

JS 的数组分支没有 `bare_block_ahead` 识别：`[ A B item { } ]` 仍拆标量；
`[ A !t item { } ]` 在值位置撞上 `!` 报 `027`（响亮但码不同）。C/C++/Lua 已对齐。

### 4.3 `@type` 的剩余三条（§4.7）

- 四端**不支持** `正则:` 逃生舱（响亮拒绝 `013`，而不是静默「永不匹配」）；
- JS 的码漂移：`用:` 环报 `014`（Rust `013`）、量词过大报 `E-LIMIT-009`（Rust `013`）；
- JS 不校验 `[D]` 的元素。

### 4.4 Lua 的「数组里引号数字 → number」

`v: [ "12" "3" ]` 在 Lua 得到 `[12, 3]`，Rust 保持字符串。等价用例 `v: [ str ]` 同样复现。
与 `@type` 无关，但同一批用例里撞见，已记 §4.7 末。

## 6. 本轮踩过的坑（别再踩）

1. **`check_from_featag` 只写 errbuf、不置 `ps->failed`** —— 抽公共函数时漏了调用点的
   `ps->failed = 1`，后果是**块被丢掉、树变空、进程认为成功**（`becc9a7` 修的）。
   现在键位置侧另加了一道防御：`finish_bare_block` 返回非 0 却没置 failed ⇒ 强制补 `012`。
2. **`sml_arr_len(NULL)` / `coerce_word(NULL)`**：数组位置裸块被拒（017）后仍走「当标量」，
   `coerce_word` 拿到 EOF 的 `v`（NULL）解引用 ⇒ 段错误。已在 `ps->failed` 处停手 +
   `coerce_word(NULL)` 返回 null。
3. **断言假通过**：`scopesCovering()` 返回**整条 scope 栈**（含祖先），高亮规则明明没生效也绿了。
   要判「最内层」scope —— `_verify_tokenize.mjs` 已加 `innerScopesAt()`。
4. **高亮规则不能要求「同一行有 `[`」**：数组通常跨行；也不能排在 `#key` 之前（会把 `a: b {` 的
   `a:` 抢走，`:` 失去 key 色）。
5. **`@type { }` 是名为 `type` 的片段**，不是类型声明 —— 判据必须是「后跟 `name:`」。
6. **量词 `stoll` 会抛异常**（C++）：`x-y` 写错会让宿主进程崩，必须 try/catch。
7. **Rust 改完忘了 `cargo build --release`**：探针用的是 `D:/internal-ref/release/smltools.exe`。

## 7. 环境事实与既存红（与本轮无关，别去"修"）

- **`python c/build_check.py --run` 有 2 条红**：`c/tests/test_codes.c` 里「未知特性名」期望
  `E-FEATURE-002`（实际 003）、「mode 子命令」期望 `E-FEATURE-006`（实际 008）。**HEAD 上同样红**，
  用 `git worktree` / `git stash` 复验过。`build_check.py`（不带 `--run`）是绿的。
- **`cargo test -p smltools` 有 5 条红**：`--to tmlanguage` / `--to highlight` 未注册 ⇒ 报
  `E-CLI-002` 而不是期望的 `E-EXT-007` / `E-MIGRATE-*`。**HEAD 上同样红**，同样复验过。
- **PowerShell 坑（本机 shell 是 PS）**：`python -c "...&..."` 里的 `&` 会被 PS 当运算符
  ⇒ 用脚本文件；`cmd > file` 会写成 UTF-16 ⇒ 用 `| Out-File -Encoding utf8` 或 python 写文件。
- **行尾**：`c/`、`cpp/`、`lua/` 的文件是 CRLF，`git` 会提示 `LF will be replaced by CRLF`；
  改文件时用 `newline="\n"` 写，提交后由 autocrlf 归一，**不会**造成整文件 diff。
