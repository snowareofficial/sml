A.3 Grammar Quick Check

Key-value:          key: value
Bare word string:   state: NY
Quoted string:      name: "John Doe"
Integer:            age: 27
Float:              ratio: 0.75
Boolean:            on: true
Null:               x: null
Object block:       a { b: 1 }    ≡   a: { b: 1 }
Array:              list: [ a b c ]
Line comments:      #  --  //
Block comments:     /* ... */     _* ... *_
Fragment define:    @name { ... }
Fragment ref:       key: &name
Contract define:    @contract Name loose { field: type ... }
Contract apply:     @is Name
include:            include "x.sml"        (inline)
                    include "ui" as ui     (namespace)
                    include "a", "b" as y  (multi-target, needs feature)
Env variable:       secret: $env.API_KEY
Escape:             "line1\nline2 \u{2744}"

A.4 version and features

The beginning of the file can declare the version:

@version v1

Complex abilities can be activated as needed:

@feature enable glob regex
include "widgets/*.sml"

By default, include+namespace+implicit-ns (minimalist three piece set) is enabled; multi/glob/regex/ext-rewrite are turned off by default and require explicit opt in.

Q1. What is the significant difference between SML and JSON?
SML naked word quotation marks, spaces/line breaks separated by commas, delimited by curly braces; There is no need to strictly add quotation marks and commas like JSON.
Q2. Judgment: SML's contract system (@contract) does not have a direct equivalent in JSON Schema.
SML builds the contract into the configuration language itself, while JSON requires an additional schema file, and the two are positioned differently.
Q3. When troubleshooting 'fields not yet effective', prioritize checking?
The ineffective configuration is often due to misspelling of field names, lack of namespace references, or discarding redundant fields in strict contracts.
